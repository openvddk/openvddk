# D-0038 — A source-compatibility header, `vixDiskLib.h`

- Date: 2026-10-10
- Contract: §10, §50 (extends D-0005)
- Status: accepted (2026-10-10).

## Context

`include/openvix/vixdisklib_abi.h` (D-0005) declares everything a new
program needs: 43 of the 46 exported functions (the three left out are
fault-injection and configuration hooks outside the public interface), all
structures with the reference's exact layout, the open flags, credential,
disk and adapter types, and `VIX_OK`, `VIX_ASYNC`, `VIX_ERROR_CODE`.

Existing programs written against VixDiskLib do not build against it as
they are: they include `vixDiskLib.h`, compare results with the `VIX_E_*`
codes, test them with `VIX_SUCCEEDED`/`VIX_FAILED`, and use the basic type
names `Bool`, `uint8` … `uint64`. With VMware's kit no longer available for
download, a developer who builds such a program has no lawful header.

## Decision

`include/vixDiskLib.h` is written by this project and generated by
`ovxtool compat-header`. It includes the ABI header and adds:

- **Error codes:** one `#define VIX_E_… ((VixError)n)` for every code in the
  library's own table (`internal/vix/codes.go`) that the ABI header does
  not define already: 266 codes. The table is the source, so the header
  and `GetErrorText` cannot disagree.
- **`VIX_SUCCEEDED(err)` and `VIX_FAILED(err)`:** a result equal to, or
  different from, `VIX_OK`.
- **The hardware-version constants** `VIXDISKLIB_HWVERSION_*` with their
  generation-8 values.
- **The basic type names** used by the generation-8 declarations (`Bool`,
  `uint8`, `uint16`, `uint32`, `uint64`), mapped to the ABI header's types,
  plus `TRUE` and `FALSE` when they are not defined. A program that gets
  them from elsewhere defines `OPENVIX_NO_BASIC_TYPES`.

Provenance as D-0005: identifiers and values only, taken from the public
generation-8 declarations and the library's own table; no comments, text
or layout reproduced. Eight names that appear in the public declarations
only inside comments (`VIX_ERROR` and seven retired codes) are not defined
here either. Compared with the public declarations, the two headers
together define every other `VIX`/`VIXDISKLIB` identifier.

## Checks

- `make compat-header` (in `make check`): the committed file equals what
  `ovxtool compat-header` renders from the current table.
- `make compat-build` (in `make check`): `tests/consumer/compat_build.c`,
  written the usual VixDiskLib way, builds against the header with
  `-Werror`, pins type sizes and a few values at compile time, initialises
  the library and checks that every code the header defines has a
  description in the library.

## Consequences

- The kit built by `make evalkit` carries `include/vixDiskLib.h` next to
  the ABI header (`tools/evalkit.sh`, `evalkit/README.md`).
- A program that also includes VMware's `vm_basic_types.h` defines
  `OPENVIX_NO_BASIC_TYPES`.
